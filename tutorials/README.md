## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/smolvlm_vision_language_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 13-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the revision it was generated from, the module SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/smolvlm_vision_language_input_manifest.json` — a top-level record naming the prompt count plus one sub-manifest per prompt under `prompts`, with the schema, ceilings, observed image, generation settings, verdict, and one recorded rejection finding from the over-long-prompt probe; `evaluation_report` (EVAL21) writes `outputs/smolvlm_vision_language_evaluation_report.json`, whose verdict is **always** `not-measurable` for this capability and which names the labelled data a real evaluation would need.
- The notebook exercises `SmolVLMPipeline` through the carried module rather than reimplementing model inference; the pipeline pins the immutable upstream revision, stages the missing weight file through `stage_missing_files(..., allow_download=True)`, loads only from a digest-verified local snapshot (`verify_snapshot`) with `trust_remote_code=False`, and wraps the prompt in the chat template. The notebook never calls `transformers`, `huggingface_hub`, `apply_chat_template` or `.generate(**` directly, and its only external dependencies are the pinned PyPI distributions and the Hub at that revision.
- Generation semantics (INF8/INF9/UNC1): greedy decoding (`do_sample=False`, `DECODING`) is the demonstrated default and stated as deterministic on a fixed device/dtype; `max_new_tokens` is explicit per call and the `truncated` flag is surfaced; the output is free text with no score or correctness signal, and the model card's hallucination observation (invented corner placement) is quoted.
- No intrinsic metric exists (EVAL9): the repository ships no metric helper, so `evaluation_report` always returns the verdict `not-measurable`; the report says so and names what a real evaluation needs (QA pairs with reference answers for VQA accuracy, reference captions for CIDEr, document-QA gold answers). Recorded `SHOULD` deviation: EVAL11 (no baseline — none is meaningful for open-ended generation without labelled data).
- Ceilings `MAX_IMAGES` = 1, `MAX_IMAGE_SIDE`, `MAX_TEXT_CHARS`, `MAX_NEW_TOKENS`/`DEFAULT_MAX_NEW_TOKENS` and `DECODING` are surfaced before the model runs, and the notebook performs no validation of its own — every prompt is checked only by the pipeline's `validate_inputs`/`generate` path; the processor's longest-edge-2048 resize and 512-px tiling are stated (DAT22/DAT23).
- The text decoder's identity as the existing DIMER `SmolLM2-360M-Instruct` language-model profile is cross-referenced (ID5).
- The default sample is a synthetic drawing generated in code; `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
